01

회원가입 추가 메타데이터

0 / 0 ▾
근거 인구통계·유입 경로는 가입 시점에 안 받으면 영영 못 받는 데이터. closed beta 동안 흘려보내는 가입자 한 명이 곧 영구 정보 손실. ICP 정의·일반 공개 시 타겟팅·카테고리 깊이 결정의 직접 입력.

입력 원칙

라디오 only · 직접 입력 0 · 30초 안에 끝나야 함 · 필수 3문항 + 선택 2문항

02

콘젠 런처 사용자 로그

0 / 0 ▾
근거 영상 생성·카테고리·실패 통계가 local-server SQLite(사용자 PC)에만 있어서 cloud에 안 모임. closed beta에서 가장 중요한 데이터인데 안 모으면 "14×19 조합 중 진짜 쓰이는 게 뭔지" 영영 알 수 없음.

수집할 이벤트 7종

event_type발생 시점핵심 필드
app_launch앱 실행 시app_version, os
video_start"영상 생성" 클릭category, style, video_length_sec
video_complete모든 단계 성공duration_ms, output_size_bytes
video_fail어느 단계든 실패fail_stage, error_code, error_message
error일반 에러error_code, error_message, stack_trace
category_select옵션 탐색 (선택)category, style
export_done결과물 저장 완료output_format, output_size_bytes

fail_stage 값: script · scene_split · tts · image_gen · video_assembly · unknown

▸ usage_events 테이블 스키마 
CREATE TABLE usage_events (
  id                BIGSERIAL PRIMARY KEY,
  user_id           INTEGER REFERENCES users(id),
  api_key           TEXT,
  event_type        TEXT NOT NULL,
  category          TEXT,
  style             TEXT,
  video_length_sec  INTEGER,
  duration_ms       INTEGER,
  output_size_bytes BIGINT,
  output_format     TEXT,
  fail_stage        TEXT,
  error_code        TEXT,
  error_message     TEXT,          -- max 1000자, redacted
  stack_trace       TEXT,          -- max 2000자, redacted
  app_version       TEXT NOT NULL,
  os                TEXT NOT NULL,
  os_version        TEXT,
  occurred_at       TIMESTAMPTZ NOT NULL,
  received_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  raw_payload       JSONB
);

CREATE INDEX idx_usage_events_user_id    ON usage_events (user_id);
CREATE INDEX idx_usage_events_event_type ON usage_events (event_type);
CREATE INDEX idx_usage_events_occurred_at ON usage_events (occurred_at);

전송 방식

closed beta = 즉시 전송 + 오프라인 큐 (real-time observability 우선). 일반 공개 후 트래픽 늘면 day-batch로 전환 (별도 ADR).

PII·보안 정책

email은 user_id 식별 용도. error_message·stack_trace는 클라이언트에서 redaction: 절대 경로 → <USER_PATH>, API key·token → <REDACTED>, 이메일 → <REDACTED_EMAIL>. 90일 후 집계 후 raw 삭제 (v1.1 별도 cron).

작업 체크리스트

  • [local] usage_event_queue SQLite 테이블 추가
  • [local] event 발행 헬퍼 logEvent(type, fields)
  • [local] 영상 파이프라인 각 단계에 logEvent 삽입 (start/complete/fail)
  • [local] 글로벌 error handler에서 logEvent('error', ...)
  • [local] flush worker (1분 cron) + 오프라인 큐 재시도
  • [local] redaction 유틸 (path · token · email)
  • [cloud] usage_events 테이블 마이그레이션
  • [cloud] routes/usage.ts POST endpoint 2개 (단일·batch)
  • [cloud] 인증 미들웨어 적용 + rate limit (분당 60)
  • [검증] 단톡방 멤버 1명 테스트 빌드 → 영상 1개 → cloud 이벤트 도착 확인
  • [검증] 오프라인 시나리오 (Wi-Fi off → 영상 1개 → on → 큐 flush)
  • [검증] redaction 동작 확인 (사용자 경로·키 마스킹)
03

Windows 코드 서명 — 결정 보류

0 / 0 ▾
근거 현재 ad-hoc 서명 → SmartScreen "확인되지 않은 게시자" 경고. 베타 멤버는 운영자가 우회 안내 가능하지만 일반 공개 시 가입 funnel 첫 단계에서 80%+ 이탈 예상.

옵션 3개 비교

옵션비용발급 기간효과추가 요건
Azure Trusted Signing 월 ~$10
(연 ~$120)		 2~3주
(Verified Publisher 검증)		 EV 수준 즉시 신뢰 MS Partner Center, D-U-N-S, 사업자등록증
OV (Sectigo/DigiCert) 연 ~$150~300 1~5일 SmartScreen 평판 누적식
(몇 주~몇 달)		 사업자 신원확인, D-U-N-S 권장
EV (Sectigo/SSL.com) 연 ~$300~600 1~2주 즉시 SmartScreen 통과 사업자 + USB 토큰/HSM 관리

공통 준비물 — 어느 옵션이든 필요

  • D-U-N-S 번호 발급 (Dun & Bradstreet, 무료, 1~5영업일)
  • 사업자등록증 스캔 (PDF)
  • 대표자 신분증 스캔
  • 도메인 이메일 준비 (작업 #4와 연계)
  • electron-builder 설정 검토 (electron-app/package.json의 build.win)
  • 단톡방 베타 사용자 OS 분포 확인 (Win 비율 ≥ 50%면 EV 우선순위 ↑)
  • 일반 공개 D-1개월 시점에 옵션 최종 선택
  • 선택 후 별도 ADR (windows-code-signing.md)에 결정 박제

관련 (범위 밖, 후속 ADR)

macOS 서명(Apple Developer + Developer ID + notarization) · 자동 업데이트(electron-updater + Squirrel)는 별도 ADR.

04

도메인 추가 연결 — 기반 작업, 1순위

0 / 0 ▾
근거 현재 콘젠 cloud-server는 Railway 기본 URL 추정. 일반 공개 시 신뢰·브랜드·이메일 일관성을 위해 자체 도메인 + 서브도메인 구조 필수. Win 서명(D-U-N-S 신청) 시 회사 이메일이 도메인 이메일이면 검증 매끄러움.

먼저 결정할 것

AICONLAB 브랜드 ↔ 콘젠 제품을 한 도메인에 묶을지 분리할지. 일반 공개 후 콘젠 상업화 계획에 따라 결정. 둘 다 사는 것도 옵션 (aiconlab.com = 메인, congen.app = 제품 랜딩).

등록 업체

업체장점단점
Cloudflare Registrar도메인 원가, 무료 SSL·DNS·DDoS등록자 영문, .kr 미지원
Gabia.kr·.co.kr 지원, 한국어가격 비쌈, 부가 서비스 푸시
Namecheap가격 합리, WhoisGuard 무료.kr 미지원

→ 권장: .com은 Cloudflare(원가), .kr 필요 시 Gabia

서브도메인 구조 (권장)

▸ 서브도메인 맵 
aiconlab.com           메인 홈페이지 (Next.js on Vercel)
www.aiconlab.com       메인으로 301 redirect
admin.aiconlab.com     /admin 영역 분리 (선택)
api.aiconlab.com       콘젠 cloud-server (Railway custom)
download.aiconlab.com  콘젠 인스톨러 호스팅
updates.aiconlab.com   electron-updater feed
docs.aiconlab.com      사용 가이드 (선택, 추후)

지금 당장 필요: aiconlab.com + api.* + download.* 3개. 나머지는 필요 시 DNS 레코드 추가.

이메일

도메인 이메일은 코드 서명 검증·고객 신뢰에 필수. 시작 단계엔 Cloudflare Email Routing 무료(forwarding) 충분. 발신 필요해지면 Google Workspace ($6/월~) 또는 Naver Works (6,000원/월~).

기본 계정: contact@ · noreply@ · admin@

작업 체크리스트

  • AICONLAB ↔ 콘젠 브랜드 분리 여부 결정 (1개 vs 2개 도메인)
  • 도메인명 후보 3~5개 + whois 조회
  • 등록 업체 결정 (.com만이면 Cloudflare 권장)
  • 도메인 구매 (연 $10~15)
  • DNS를 Cloudflare로 위임
  • Vercel에 메인 도메인 연결
  • Railway에 api.* · download.* · updates.* custom domain 연결
  • 이메일 서비스 선택 + MX 레코드 추가
  • 기본 이메일 3~5개 생성
  • noreply@ 발신 테스트 (콘젠 인증 메일)

다른 작업과 묶이는 지점

  • #3 Win 서명: D-U-N-S·Verified Publisher 시 도메인 이메일이 매끄러움
  • 자동 업데이트: updates.aiconlab.com feed URL이 electron-updater 설정에 박힘
  • 콘젠 cloud-server URL: api.aiconlab.com으로 옮기면 electron-app·local-server의 cloud-client URL 환경변수 일괄 수정 필요

본 ADR 범위 밖 (후속)

  • macOS 코드 서명 — Apple Developer + Developer ID + notarization. 별도 ADR.
  • 자동 업데이트 — electron-updater + Squirrel. Win 서명 결정 후 별도 ADR.
  • 결제 자동화 — Toss·Stripe. 무통장 입금 폐기 시점에 별도 ADR.
  • 대시보드 코드 구현 — 본 4개 작업 완료 후 dashboard-v1 Stage A 시작.
