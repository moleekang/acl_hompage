4. RLS 정책 — 보안의 마지막 방어선

원칙
모든 테이블 RLS ENABLED. UI 라우팅이 깨져도 DB가 거부. SECURITY DEFINER 함수 is_active() / is_admin()로 정책 단순화.

공개 데이터 (posts, products)

-- 모두 읽기, admin만 쓰기 CREATE POLICY "read_published" ON posts FOR SELECT USING (published_at IS NOT NULL); CREATE POLICY "admin_write" ON posts FOR ALL USING (is_admin()) WITH CHECK (is_admin());

위키 (자유 협업)

-- active 멤버 누구나 읽기·쓰기 CREATE POLICY "wiki_member_read" ON wiki_pages FOR SELECT USING (is_active()); CREATE POLICY "wiki_member_write" ON wiki_pages FOR INSERT WITH CHECK (is_active()); CREATE POLICY "wiki_member_update" ON wiki_pages FOR UPDATE USING (is_active()) WITH CHECK (is_active()); -- 삭제는 admin만 (soft delete)

이벤트 (초대된 멤버만)

-- 본인이 초대된 이벤트만 보임 CREATE POLICY "event_invited_read" ON events FOR SELECT USING ( is_admin() OR EXISTS ( SELECT 1 FROM event_invitations ei WHERE ei.event_id = events.id AND ei.user_id = auth.uid() ) ); CREATE POLICY "event_admin_write" ON events FOR ALL USING (is_admin());

profiles (자기 자신 + admin)

-- 본인 row만 읽기, admin은 전체 CREATE POLICY "profile_self_read" ON profiles FOR SELECT USING (id = auth.uid() OR is_admin()); -- status·role 변경은 admin 전용 CREATE POLICY "profile_admin_update" ON profiles FOR UPDATE USING (is_admin());
함정 주의
is_admin()를 SECURITY DEFINER로 만들지 않으면 profiles SELECT 정책이 자기참조해서 무한루프. 반드시 SECURITY DEFINER + 명시적 schema 지정.

5. 핵심 테이블 — profiles · products · posts

profiles
auth.users 확장. 멤버십 상태·역할의 단일 진실.
CREATE TABLE profiles ( id uuid PRIMARY KEY REFERENCES auth.users ON DELETE CASCADE, status text NOT NULL DEFAULT 'pending', -- pending | active | suspended role text NOT NULL DEFAULT 'member', -- member | admin nickname text, avatar_url text, applied_at timestamptz NOT NULL DEFAULT now(), approved_at timestamptz, approved_by uuid REFERENCES profiles(id), CHECK (status IN ('pending','active','suspended')), CHECK (role IN ('member','admin')) ); -- auth.users INSERT 시 자동 profiles row 생성 CREATE TRIGGER on_auth_user_created AFTER INSERT ON auth.users FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
products
자동화앱 카드. Congen + Coming Soon 카드들이 들어감.
CREATE TABLE products ( slug text PRIMARY KEY, name text NOT NULL, pitch text NOT NULL, status text NOT NULL, -- beta | coming | live | retired hero_image text, body_mdx text, release_at text, -- "2026 Q3" 같은 자유 표기 order_idx int NOT NULL DEFAULT 0, published boolean NOT NULL DEFAULT false, created_at timestamptz DEFAULT now(), updated_at timestamptz DEFAULT now() );
posts
팀 블로그. 현재 posts.ts → 그대로 마이그레이션.
CREATE TABLE posts ( slug text PRIMARY KEY, title text NOT NULL, sub text, body_mdx text NOT NULL, cat text NOT NULL, author_id uuid REFERENCES profiles(id), read_time text, published_at timestamptz, created_at timestamptz DEFAULT now(), updated_at timestamptz DEFAULT now() );

6. 위키 테이블 — 자유 협업 + 수정 이력

wiki_pages — 현재 상태
한 슬러그 = 한 페이지. body_mdx는 최신 본문만 가짐.
CREATE TABLE wiki_pages ( id uuid PRIMARY KEY DEFAULT gen_random_uuid(), slug text UNIQUE NOT NULL, title text NOT NULL, body_mdx text NOT NULL, created_by uuid REFERENCES profiles(id), updated_by uuid REFERENCES profiles(id), created_at timestamptz DEFAULT now(), updated_at timestamptz DEFAULT now(), deleted_at timestamptz -- soft delete (admin) ); CREATE INDEX wiki_pages_updated_idx ON wiki_pages (updated_at DESC) WHERE deleted_at IS NULL;
soft delete 이유
자유 협업이라 실수·악의로 페이지가 날아갈 위험. deleted_at으로 표시만 하고 admin이 복원 가능.
wiki_revisions — 모든 저장의 스냅샷
한 페이지의 매 저장마다 한 row. 자유 협업의 안전망.
CREATE TABLE wiki_revisions ( id uuid PRIMARY KEY DEFAULT gen_random_uuid(), page_id uuid NOT NULL REFERENCES wiki_pages(id) ON DELETE CASCADE, title text NOT NULL, body_mdx text NOT NULL, edited_by uuid REFERENCES profiles(id), edited_at timestamptz DEFAULT now(), comment text -- 수정 사유 (선택) ); CREATE INDEX wiki_rev_page_time_idx ON wiki_revisions (page_id, edited_at DESC); -- wiki_pages UPDATE 시 자동으로 -- wiki_revisions에 이전 본문 INSERT 트리거
운영 규칙
wiki_revisions는 append-only. UPDATE·DELETE 정책 자체를 만들지 않음. 이력은 영원.

7. 이벤트 테이블 — 초대제 공유회

events
공유회·워크샵 기본 정보. 결제는 미래(price_cents 컬럼만 미리 두기).
CREATE TABLE events ( id uuid PRIMARY KEY DEFAULT gen_random_uuid(), slug text UNIQUE NOT NULL, title text NOT NULL, body_mdx text, starts_at timestamptz NOT NULL, ends_at timestamptz, location text, -- 온/오프라인 표기 capacity int, price_cents int NOT NULL DEFAULT 0, -- 0 = 무료. 결제는 Phase 6+ status text NOT NULL DEFAULT 'draft', -- draft | open | closed | done created_at timestamptz DEFAULT now() );
결제 미래 대비
price_cents 컬럼은 지금 두고 값은 0. Phase 6에서 event_payments 테이블 추가하면 끝.
지금 결제 로직은 만들지 않음.
event_invitations — 게이트의 핵심
운영자가 명시 초대한 user만 이 이벤트를 볼 수 있다. RLS의 USING 조건이 이 테이블을 본다.
CREATE TABLE event_invitations ( event_id uuid NOT NULL REFERENCES events(id) ON DELETE CASCADE, user_id uuid NOT NULL REFERENCES profiles(id) ON DELETE CASCADE, invited_by uuid REFERENCES profiles(id), invited_at timestamptz DEFAULT now(), viewed_at timestamptz, -- 멤버가 첫 조회 시 기록 rsvp text DEFAULT 'pending', -- pending | going | declined PRIMARY KEY (event_id, user_id) ); CREATE INDEX inv_user_idx ON event_invitations (user_id);
UX 흐름
/insights = "내가 초대받은 공유회" 목록. 초대 안 받은 멤버에겐 "현재 초대된 공유회가 없어요" 화면.

🔁 v1 → v1.1 변경 — 빌드 중 확정된 차이

가입 정책

v1 (초안) — 신청 승인제
가입 → status=pending → 운영자 승인 → status=active
v1.1 (확정) — 자유 가입 + 별도 위키 승급
가입 = 즉시 guest. 위키 권한은 운영자가 member로 승급 시 부여.

profiles 컬럼

-- v1 → v1.1 status: 'pending'|'active'|'suspended' → 'active'|'suspended' (pending 제거) role: 'member'|'admin' → 'guest'|'member'|'admin' (guest 추가) + helper is_wiki_member() -- role IN ('member','admin') AND status='active'

위키 RLS

CREATE POLICY wiki_pages_select ON wiki_pages FOR SELECT USING (is_wiki_member()); -- 이전엔 is_active()

인프라 발견

launcher는 Supabase 안 씀
launcher는 Express + Railway PG + raw pg + jsonwebtoken. acl_hompage는 별도 Supabase 프로젝트로 진행.
Google OAuth Client는 재사용 가능 (redirect URI만 추가).
